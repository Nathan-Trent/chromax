A standalone Node.js AI system that integrates with any ERP or business platform. Knows the business inside out — answers questions, monitors health, and sends intelligent summaries.
Standalone Node.js system Integrates with any ERP External customer widget Internal business assistant System health monitoring Email summaries Chromax is client #1

Build note: This is a separate system from the Chromax website and ERP. It integrates with Chromax as its first client but is architected to work with any business. Chromax is the testing and validation platform — not the product itself.

3. Internal Mode — System Health Monitoring

This is what separates this product from a generic chatbot. Staff can ask why the system is slow or broken — and get a real, technical answer in plain language.

Staff: "Why is the ERP so slow right now?"
I checked the server metrics. Here's what I found:

• CPU usage: 87% (normal is below 60%)
• The slow query log shows a report query has been running for 4 minutes — this is blocking other requests
• Memory: 78% — not critical but elevated

Likely cause: Someone ran a large report (possibly the monthly sales export). The system should return to normal in 3–5 minutes once that query completes. If it doesn't resolve, restart the queue worker.
Staff: "The payment page keeps failing. What's wrong?"
I checked the error logs from the last 30 minutes:

• 14 failed payment requests — all starting at 14:32
• Error: "Paystack API timeout after 30s"
• External ping to api.paystack.co: 503 response

This is a Paystack outage — not an issue on your end. You can check their status at status.paystack.com. Orders placed in the last 30 minutes may need to be retried by customers once they restore service.
Staff: "The dashboard is showing wrong stock numbers."
I checked the sync logs between the dashboard and ERP:

• Last successful sync: 2 hours ago
• 3 sync events failed with: "Connection refused — Redis queue worker not running"
• Queue depth: 47 pending events backed up

The queue worker has stopped. This is why stock updates aren't coming through. Fix: SSH to the server and run: pm2 restart queue-worker. The backlog will clear automatically once it restarts.
Staff: "Why can't I log in? It says invalid credentials."
I checked the authentication logs:

• 6 failed login attempts for your email in the last 10 minutes
• After 5 failed attempts, accounts are temporarily locked for 15 minutes
• Lock expires at: 15:47

Your account will unlock automatically in 8 minutes. If you didn't make those attempts, contact your admin — it may indicate someone is trying to access your account.
What the health monitor reads

Internal log access

  • Server CPU, memory, and disk usage (via system metrics API)
  • Database slow query log — queries taking longer than threshold
  • Application error log — 4xx and 5xx errors with frequency and stack traces
  • Queue worker status — running, stopped, backlog depth
  • Sync event log — success/failure per event with payload summary
  • Auth log — failed login attempts, locked accounts

External monitoring

  • Ping check every 5 minutes — is the ERP responding?
  • API dependency checks — Paystack, Stripe, external services
  • Response time tracking — flags if average response time spikes
How it works technically
  • A lightweight health agent runs on the ERP server — reads logs and system metrics, exposes a local API endpoint
  • The AI chatbot calls this endpoint when a health question is asked
  • For external monitoring — the AI system pings the ERP from outside every 5 minutes and logs response times
  • When a health issue is detected proactively — e.g. CPU above 90% for 5+ minutes — an email alert fires automatically
  • The AI synthesises raw log data into plain-language explanations
  • For Chromax specifically — the agent connects directly to the Laravel log files and MySQL slow query log

This summary was generated automatically. Reply to this email or open the assistant in your dashboard to ask follow-up questions.

Email schedule options
  • Daily digest — sent every morning at a time configured by the owner. Covers previous day's activity, pending items, any system alerts.
  • Weekly report — sent every Monday morning. Full week summary with trends, comparisons, and recommendations.
  • Both — owner can opt into daily + weekly simultaneously.
  • Alert-only — no scheduled summary, only emails when something needs immediate attention.
  • Schedule and alert thresholds configured during onboarding and editable at any time.
What triggers an immediate alert email
  • ERP becomes unreachable (external ping fails 3 times in a row)
  • CPU or memory on ERP server exceeds 90% for more than 5 minutes
  • Product stock drops below reorder threshold
  • Revenue category drops more than 25% week-on-week
  • High-value customer inactive beyond configured threshold
  • Queue worker stops — sync events backing up
  • External payment gateway returning errors

5. Onboarding Flow — Connecting Any Business System

Flexible connection — client chooses whichever method suits their setup. The onboarding wizard guides them through it step by step.

1
Create account and name your assistant
Business name, industry type, primary contact email, timezone, preferred email summary schedule (daily / weekly / alerts only). This is the only required step before anything else.
2
Upload knowledge base — for the external customer widget
Upload product catalogue documents (PDF, Word, Excel, CSV), pricing sheets, policy documents, FAQs. These are chunked, embedded, and stored in the AI's vector database. The external customer widget uses this knowledge to answer customer questions.

Supported formats: PDF · DOCX · XLSX · CSV · plain text. Multiple files, any order. Can add more documents later at any time.
3
Connect your business system — for the internal assistant
Client chooses one of three connection methods:
Option A — Recommended Install the health agent + provide database read credentials
A lightweight Node.js agent is installed on the ERP server. It exposes a local API that the AI queries for logs, system metrics, and health data. Separately, read-only database credentials are provided so the AI can query business data (orders, sales, stock etc.).
npm install -g @ai-assistant/agent
ai-agent init --port 4200 --log-path /var/log/app
Option B ERP exposes a standard API
If the client's ERP already has an API, the AI connects to it directly using provided credentials. The onboarding wizard maps the API endpoints to the AI's tool functions. Works well for standard ERPs (Odoo, Sage, SAP with API access).
Base URL: https://your-erp.com/api
Auth: Bearer token or API key
Wizard maps: /orders · /stock · /sales · /customers
Option C Direct database read access
For custom or legacy systems with no API — provide read-only database credentials (MySQL, PostgreSQL). The AI queries the database directly using predefined safe read-only queries. No write access ever granted.
DB host, port, database name
Read-only user credentials
Wizard identifies key tables automatically
4
Configure alert thresholds and email schedule
Set which events trigger immediate emails. Set stock reorder thresholds, revenue drop percentage threshold, customer inactivity threshold. Configure daily and/or weekly summary schedule and delivery time.
5
Get the embed snippet — for the external widget
One script tag to paste into the business website. The widget appears immediately. Style (colour, position, greeting message) configurable from the dashboard without touching code.
<script src="https://cdn.ai-assistant.com/widget.js" data-client="CHROMAX-001"></script>
6
Embed internal assistant in ERP dashboard
For the internal mode — a React component or iframe embed placed inside the ERP dashboard. For Chromax specifically, this is a React component dropped into the existing Laravel/React ERP dashboard. For other clients, an iframe snippet works with any system.
import AIAssistant from '@ai-assistant/react';
<AIAssistant clientId="CHROMAX-001" mode="internal" />

6. Tool Functions — How the AI Queries Business Data

Pattern: The AI never writes raw SQL or touches data directly. Each capability is a named function that runs a safe read-only query and returns structured JSON. The AI calls these functions based on what the question requires. Adding a new capability = adding one new function. Removing one = deleting it. No retraining needed.

7. Proactive Schedule — When the System Acts Automatically

Daily · configurable time
Daily digest email — yesterday's orders, revenue, fulfilment status, any overdue items, system health snapshot. Only sent if owner has opted into daily summaries.
Weekly · configurable day
Full weekly report email — revenue vs last week, top products, new leads, B2B offer outcomes, customer retention flags, staff activity summary, system health week summary.
Every morning · 8am
Scan for overdue orders (packed but not dispatched), unanswered B2B offers older than 12 hours, and low stock items. Queue alert emails for anything found.
Every hour
Check B2B offer response times. If an offer has no response after 22 hours, alert the sales contact by email.
Every 5 minutes
External ping to ERP. If 3 consecutive pings fail — immediate alert email to owner and admin contact. Pings resume silently when service restores.
Every 10 minutes
Read server health metrics from the agent. If CPU above 90% or memory above 95% for more than 10 minutes consecutively — immediate alert email with diagnosis.
Weekly · Sunday
Customer retention scan — identify high-value customers inactive beyond the configured threshold. Include in next weekly report with suggested action.
Weekly · Sunday
Sales trend analysis — compare this week vs last 4 weeks per category. If any category down more than 25%, generate loss risk section for weekly report and optionally send an immediate alert.
Real-time · event-driven
Stock drops below reorder threshold → immediate alert. Payment gateway starts returning errors → immediate alert. Queue worker stops → immediate alert. All triggered by the monitoring functions, not cron.

8. Technical Stack

Core principle: The AI system is Node.js only. It does not share a codebase with Chromax (Laravel) or the website (Next.js). It communicates with those systems via APIs and database connections — it never imports or merges with them. This keeps it portable and reusable across different clients.

LayerTechnologyWhy
Core runtime
Node.js + Express
Your existing stack. Fast async I/O for tool function calls and streaming responses.
AI inference
Claude API (tool use)
Tool use / function calling handles the reactive mode. Structured outputs for email generation.
RAG pipeline
LangChain.js + pgvector
Document chunking, embedding, and retrieval for the external customer widget knowledge base.
Embeddings
nomic-embed-text via Ollama
Runs locally — free, fast, no API cost per document. Each client's knowledge base embedded on their server.
Vector database
pgvector (PostgreSQL)
No extra service — vector similarity search as a PostgreSQL extension.
Application DB
PostgreSQL (Supabase)
Stores client configs, conversation logs, alert settings, email schedule, onboarding state.
Scheduled jobs
node-cron
Lightweight cron inside Node process. Each job calls the relevant tool functions and triggers email dispatch.
Email delivery
Nodemailer + SendGrid
Nodemailer for sending, SendGrid for deliverability and tracking open rates.
Health agent
Node.js microservice
Lightweight process installed on the client's ERP server. Reads logs and system metrics, exposes local REST API.
External monitoring
Custom ping service (Node)
Runs on the AI system server. Pings client ERP endpoints every 5 minutes, logs response times and status codes.
Widget embed
Vanilla JS + React (iframe)
Vanilla JS for the external customer widget — no framework dependency, works on any website. React component for internal ERP embed.
Client dashboard
Next.js
Onboarding portal, document uploads, alert configuration, email schedule settings, usage analytics.
